# Migration: standalone GLOMAP → COLMAP `global_mapper`

## What changed

COLMAP now includes the GLOMAP global structure-from-motion pipeline.
Current COLMAP documentation exposes it through this command:

```text
colmap global_mapper
```

See the official [COLMAP CLI reference](https://colmap.github.io/cli.html) for the current command.
The Melkor wrapper checks for this command before it starts work.
Melkor no longer installs a separate GLOMAP checkout.

## Why Melkor stopped installing standalone GLOMAP

The previous `scripts/setup_glomap.sh` did a mutable clone of the standalone repository:

```bash
git clone https://github.com/colmap/glomap.git
git pull origin main   # tracking a moving branch
```

The v2 hardening program forbids this pattern.
A build that tracks an upstream branch at run time is not reproducible.
Melkor has retired that mutable installer.

Use a **pinned** COLMAP build with a verified `global_mapper` command.
A future supported adapter must record and verify that build identity.

## What to run instead

You need a COLMAP build recent enough to include `global_mapper`. Confirm it:

```bash
colmap global_mapper --help
```

If that command is missing, the installed COLMAP does not expose the integrated pipeline.
Install a suitable COLMAP build.
Do **not** fall back to the standalone GLOMAP repository.

### Before (deprecated)

```bash
# Standalone GLOMAP, cloned and built by setup_glomap.sh
./glomap mapper \
  --database_path database.db \
  --image_path images/ \
  --output_path sparse/
```

### After (COLMAP global mapper)

```bash
# Feature extraction and matching, then global mapping, all through COLMAP.
colmap feature_extractor --database_path database.db --image_path images/
colmap exhaustive_matcher --database_path database.db

# Use this copied database when reliable focal-length priors are unavailable.
cp database.db database-global.db
colmap view_graph_calibrator --database_path database-global.db

colmap global_mapper \
  --database_path database-global.db \
  --image_path images/ \
  --output_path sparse/
```

Current COLMAP documentation recommends `view_graph_calibrator` when reliable intrinsics are
unavailable.
The command changes camera intrinsics and two-view geometry in place, so use a database copy.
You can omit the calibration step when the database already has reliable camera intrinsics.
The temporary Melkor wrapper does not run this step.

The output in `sparse/` is a standard COLMAP sparse model. The incremental mapper produces the
same format. Thus, existing downstream COLMAP consumers continue to work.

## An honest note on speed

Global mapping and incremental mapping make different robustness and precondition trade-offs.
The COLMAP documentation describes these differences. Global mapping is **not** universally
faster or better for every dataset.

Melkor does not repeat an unqualified "N× faster" figure:
each performance comparison must use a benchmark run on named datasets and hardware. Record the
run under `benchmarks/`. Choose the mapper for your data. For important work, use a measurement
that you can reproduce.

## Status in Melkor

Melkor does not yet provide a manifest-based COLMAP adapter.
The temporary `scripts/glomap_wrapper.sh` command runs `colmap global_mapper`.
It checks the required sparse-model files after the external command returns.

The wrapper does not pin the COLMAP revision or record an immutable run manifest.
Treat this document as a manual development procedure.
The standalone GLOMAP installer is gone regardless.
