# Melkor Viewer

Melkor Viewer uses SparkJS and three.js to show Melkor PLY and SPZ output. It provides:

- Local file opening and camera controls
- Progressive loading
- A bounded-memory 4D player
- A Tauri v2 desktop shell
- Playwright render tests

The frontend has no compile step. `index.html` contains the document shell and import map.
`bootstrap.js` reports missing application modules as visible fatal states.
`viewer.css` contains presentation rules. `viewer.js` owns rendering and interaction state.

`local-file-validator.js` checks bounded containers before Spark receives local bytes.
The validator uses a module worker, so large checks do not block viewer controls.

## Open your own splat

Choose **Open local splat** or drag one file anywhere over the viewer. PLY,
SPZ, SPLAT, KSPLAT, and bundled SOG/ZIP files are supported up to 256 MiB. The
file is streamed directly into Spark inside the browser or desktop webview: it
is never uploaded, copied into `public/`, or granted persistent filesystem
access. Selecting another local file replaces the retained `File` reference,
so the viewer does not keep an unbounded history in memory.

Local input has these limits:

- At most 5,000,000 splats
- Binary little-endian or big-endian PLY records
- A PLY header of at most 64 KiB
- No PLY list properties or extra elements
- Exact PLY record sizes
- Graphdeco PLY fields or basic point-cloud PLY fields
- No mixed `f_dc_*` and RGB color groups
- No mixed `opacity` and `alpha` fields
- Finite numeric values that fit float32
- Log scales from `-12` through `9`, which is the Spark packed range
- At most 512 MiB of decoded SPZ data
- An SPZ expansion ratio of at most 100:1
- Valid SPZ v1-v3 quaternion encoding
- Valid SPZ LOD child ranges
- One KSPLAT section with a header count that matches its records
- Finite KSPLAT positions, scales, rotations, bucket centers, and SH values
- At most 4,096 ZIP/SOG entries
- At most 512 MiB of expanded ZIP/SOG data
- A maximum ZIP/SOG expansion ratio of 100:1
- One strict UTF-8 SOG `meta.json` file of at most 64 KiB
- Finite SOG values that fit the Spark decoder domains
- Static PNG or WebP SOG images of at most 5,000,000 pixels each
- An SH centroid image of at least 960 by 1024 pixels
- At most 256 MiB for all decoded SOG RGBA images

Local opening works offline after the viewer itself has loaded. Invalid,
empty, oversized, or damaged files leave the current scene visible and show a
recoverable error. The file picker is the cross-platform fallback. HTML5 drag
and drop is also enabled in the Tauri shell.

If a 4D frame fails, retry the frame or keep the current frame. You can then select another scene.

Selecting another file or scene cancels the active validation worker.

## Scene fixtures

The normal developer setup exercises all four Spark container paths plus a
temporal sequence:

| Scene | Format | Size | Provenance |
|---|---:|---:|---|
| Snowy Street | SPZ | ~982K splats | external sparkjs.dev test fixture |
| Valley | SPZ | 500K splats | external sparkjs.dev test fixture |
| Sutro Tower | SOG (`.zip`) | ~2.0M splats | external sparkjs.dev test fixture |
| Wave Field | SPLAT | 4,096 splats | generated by `make-static-demo.js` |
| Distant Igloo | SPZ | 347K splats | external sparkjs.dev test fixture |
| Igloo · PLY | PLY | 347K splats | optional Melkor conversion from Distant Igloo |
| Wave · 4D | per-frame PLY | 24 frames | generated by `make-4d-demo.js` |

External captures are gitignored and are never redistributed in the desktop
app. Their source pages do not publish a standalone redistribution license, so
they remain opt-in developer/test fixtures. The packaged viewer contains only
the project-owned generated demos. See
[ASSET_PROVENANCE.md](ASSET_PROVENANCE.md) and
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

At startup, the viewer probes every scene and hides files that are absent.
Successful bundled-scene selections are reflected in the `?scene=<id>` query
parameter, so the current scene can be bookmarked or shared. Unknown or
unavailable IDs fall back to the first available scene. Opening a local file
removes the parameter so a private filename never enters the URL.

## Setup

```bash
cd viewer

# Full render-test setup: MIT runtime plus external developer fixtures.
./fetch-assets.sh

npm ci --ignore-scripts
npx playwright install chromium
```

Every download is SHA-256 checked before it is moved into place. For the
desktop runtime without external scenes:

```bash
./fetch-assets.sh --runtime-only
```

This fetches three.js r180 and Spark 2.1.0. Then, it deterministically
generates the static SPLAT and 4D PLY fixtures.

The external SPZ fixture does not declare its unit or color space.
Set `MELKOR_IGLOO_UNIT_TO_METER` and `MELKOR_IGLOO_COLOR_SPACE` only after verification.
When both values exist, the setup tests native conversion and Spark's PLY loader.
The conversion writes `ply:graphdeco-3dgs-v1` in the SPZ coordinate frame.
The viewer rejects `ply:melkor-canonical-v1` because Spark does not decode its fields.

## Run

```bash
bun run serve
# http://127.0.0.1:8771/
```

By default, `serve.js` binds to loopback and accepts only GET and HEAD. It
exposes only the viewer entry files, `vendor/`, and `public/`. It rejects traversal and
malformed URLs. HEAD responses contain correct MIME and length metadata.

The server sets a restrictive development CSP and other browser security headers.
Development supports `PORT`, `HOST`, and `QUIET=1`. `PORT` must be from 1 through 65535.

### Controls

| Input | Action |
|---|---|
| Open local splat / file drop | open a local PLY, SPZ, SPLAT, KSPLAT, or SOG/ZIP without uploading |
| Scene buttons | switch scene |
| Front / Side / Top / 3/4 | select a named camera view |
| Orbit | toggle automatic orbit |
| Reframe | recompute bounds. Resume orbit when reduced motion is off. |
| Help | open the complete input guide |
| Drag / scroll | orbit or dolly. Enter manual mode. |
| WASD / arrows | fly in manual mode |
| Q / E | move down / up |
| Shift / CapsLock / Ctrl | speed ×5 / ×10 / ×0.2 |
| Timeline arrows | select a 4D frame |
| Timeline Home / End | select the first or final 4D frame |
| Escape | close help, a file target, or a dismissible error dialog |

Controls are keyboard accessible, expose pressed/busy state, remain inside a
narrow mobile viewport, and honor `prefers-reduced-motion` by disabling
automatic orbit and temporal autoplay.

The viewer supports a 667 by 375 landscape layout and a 320 by 568 portrait layout.
The panels use safe-area insets on devices with display cutouts.

The viewport has an accessible name and a control description. The camera toolbar reports the selected named view.
Error messages use modal alert dialogs. Each dialog traps focus and restores focus when it closes.

The camera toolbar has one Tab stop. Arrow keys, Home, and End move this stop.
Mandatory error dialogs have no Dismiss action. Escape does not close them.
The 4D timeline reports frame values, playback state, and buffering state.

## Desktop app

The Tauri v2 shell uses WKWebView on macOS, WebKitGTK on Linux, and WebView2 on Windows.
The macOS package requires macOS 14.0 or later.
This baseline supplies Safari 17 WebKit, including the worker `OffscreenCanvas` WebGL support that SOG decoding needs.
The desktop window has a minimum size of 640 by 360 CSS pixels.
`../assets/logo.svg` is the source for the web favicon and all native app icons.
Development mode starts the Bun server:

```bash
bun run app
```

For a local desktop build, use Rust 1.88 and Tauri CLI 2.11.4:

```bash
./fetch-assets.sh --runtime-only
cargo install tauri-cli --version 2.11.4 --locked
bun run app:build
```

The pre-build step regenerates project-owned demos. It stages this exact
allowlist:

- `index.html`
- The application modules and local validator worker
- The Melkor favicon
- Four digest-checked runtime modules
- Generated SPLAT and 4D files in the manifest
- The project license and notices

It never recursively embeds `public/`, external captures, `node_modules/`, or
`src-tauri/target/`. A strict CSP is enabled in the packaged webview.
The frontend has no Tauri IPC permissions.

Local bundles are unsigned developer artifacts. Signing/notarization and a
tag-driven release artifact workflow are separate release gates.

## Loading and framing

- Import maps resolve three.js and Spark entirely from `vendor/`. Spark's
  worker/WASM payload is embedded in its checked module.
- The first `SplatMesh` is attached before its download completes, enabling
  progressive rendering. A scene switch keeps the current mesh until the next
  one is ready.
- A monotonic load token makes racing scene changes latest-request-wins.
- Bounds are computed from an opacity-filtered center sample because some
  packed formats do not expose finite `getBoundingBox()` results.
- WebGL context loss and asset/manifest/frame failures become visible,
  recoverable states rather than a permanently blank canvas.

## 4D sequences

A temporal scene is a directory containing one PLY or SPZ per frame and:

```json
{
  "fps": 12,
  "frames": ["time_00000.ply", "time_00001.ply"]
}
```

The player retains a circular window around the playhead. It prefetches future
frames and evicts frames outside the window. It stalls during buffering and
wraps from the final frame to frame zero. The latest request wins during a
seek. Failed frames get three bounded retries with exponential backoff. The
viewer also provides an explicit retry action.

The player starts at most four frame loads at one time.

Create fixtures or package a real per-frame export with:

```bash
node make-4d-demo.js
node pack-4d.js /path/to/frames --out public/splats/4d/my-scene
node pack-4d.js /path/to/frames \
  --spz \
  --melkor ../build/dev/melkor \
  --allow-loss LOSS_COLOR_SPACE_METADATA_DROPPED \
  --allow-loss LOSS_COORDINATE_METADATA_DROPPED \
  --out public/splats/4d/my-scene-spz
```

The two approvals permit SPZ to omit the source color-space and coordinate metadata.

The packer stages the complete sequence before it changes the output directory.
It writes each Melkor loss report to `loss-reports.ndjson` for an SPZ sequence.
The packer requires a new output directory.
It publishes that directory with an atomic no-replace rename.

The packer also accepts these Melkor options with `--spz`:

- `--input-profile`
- `--source-frame`
- `--source-unit-to-meter`
- `--source-color-space`
- `--output-antialiased`
- `--max-sh-degree`
- `--limits-profile`
- `--allow-loss`

The automation API exposes `load`, `setView`, `setAngles`, `setOrbit`,
`waitRendered`, `getStats`, `play4D`, `pause4D`, `seek4D`, and `get4DState`
under `window.__viewer`.

## Tests

```bash
npm test
npm run test:headed
npm audit --audit-level=high
```

The Playwright suite checks:

- Asset serving and server fail-closed behavior
- Offline local file picker, repeat-open, drag/drop, and invalid-file recovery
- WebGL2 rendering, plausible counts, and nonblank camera views
- Camera, orbit, and manual interactions with mobile bounds
- Short-screen layout, keyboard help, focus management, and accessible state
- Reduced-motion behavior
- Progressive first load and safe scene switching
- Bounded, wrapping 4D playback and on-demand seek
- Out-of-order seek races and finite retry/recovery
- Optional producer-to-player SPZ playback

Screenshots are written to the gitignored `screenshots/` directory.
On CI runners without a GPU, the tests decode each container format and wait
for a rendered frame. The generated 4K Wave fixture runs the framebuffer and
multi-camera assertions under SwiftShader. Local runs retain the complete
four-view visual matrix for each fixture. Set
`VIEWER_FULL_RENDER=1` to force that matrix in CI-like environments.

## Adding an asset

1. Record the creator, immutable source, redistribution license, attribution,
   and SHA-256 in `ASSET_PROVENANCE.md`.
2. If redistribution rights are unclear, keep it an external fixture and do
   not add it to `stage-dist.js`.
3. Add its checksum-pinned downloader entry and `SCENES` metadata.
4. Add a Playwright count/render case when it is a stable CI fixture.

Only project-owned assets or assets with explicit redistribution rights may
enter the desktop staging allowlist.
